# 機能追加 準備ドキュメント（記録項目の拡充・入力体験の改善）

作成日: 2026-08-01 ／ 対象: 草野球記録アプリ（https://baseball-score-app-seven.vercel.app）

## 1. 現状サマリ

技術スタックは Next.js 14 (App Router) + Supabase (Auth/Postgres/RLS) + Tailwind + Recharts。GitHub `du0000du/baseball-score-app` の main ブランチへの push で Vercel が自動デプロイされる。開発環境はこのセッション内にクローン済みで、`.env.local` 設定済み、`npm run build` 成功確認済み（コミット `893aec6` 時点）。

### 現在記録できる項目（at_bats テーブル）

打順（1〜12）、打席結果15種（安打・二塁打・三塁打・本塁打・三振・ゴロ・フライ・内野フライ・ライナー・四球・死球・犠打・犠飛・失策・野選）、打球方向11方向、守備位置（DH含む10種）、打点数、得点、盗塁数、盗塁死、カウント（B/S）、入力方法（manual/nlp ※nlpは未実装のスキーマ準備のみ）。

投手成績（pitching_stats）は投球回・被安打・被本塁打・奪三振・与四球・与死球・失点・自責点・完投・球数・勝敗S/H。

### 入力体験の現状

打席入力ページ（`app/(protected)/games/[id]/at-bats/page.tsx`、約1,100行）にフォームが集約。既存の省力化機能として「直前打席のコピー（P-4）」「試合の複製（R-3）」「一括登録（R-2）」「前回試合日の記憶（R-5）」があり、オフラインキュー（`lib/offline-queue.ts`）とクエリキャッシュも実装済み。

## 2. 機能候補（記録項目の拡充）

| # | 候補 | DB変更 | 概要 |
|---|------|--------|------|
| A-1 | 打球の強さ・性質 | at_bats に列追加 | 強いゴロ/弱いフライ等。スプレーチャートの表現力が向上 |
| A-2 | 対戦投手情報 | games or at_bats に列追加 | 左右・タイプ（速球派/軟投派）。左右別成績の分析が可能に |
| A-3 | 打席ごとのメモ | at_bats に notes 列追加 | 「初球打ち」「狙い球」など振り返り用の自由記述 |
| A-4 | 走塁詳細 | at_bats に列追加 | 進塁（単打で二塁へ等）、牽制死、走塁死の区別 |
| A-5 | 守備記録 | 新テーブル fielding_records | 刺殺・補殺・失策・好プレー。守備率の算出が可能に |
| A-6 | 出場情報 | games に列追加 | 先発/途中出場、代打・代走、出場イニング |
| A-7 | 試合環境 | games に列追加 | 天候・気温・グラウンド状態（既に stadium はあり） |

マイグレーションは `supabase/migrations/008_xxx.sql` として追加し、`lib/supabase/types.ts` と `lib/stats.ts`、stats ページの集計を合わせて更新する。

## 3. 機能候補（入力体験の改善）

| # | 候補 | 規模 | 概要 |
|---|------|------|------|
| B-1 | クイック入力モード | 中 | 結果→方向を2タップで確定するワンスクリーンUI。詳細は後から追記 |
| B-2 | 自然言語入力 | 中〜大 | 「センター前ヒット、打点1」などの文を解析して登録。スキーマの input_method='nlp' が既に準備済み |
| B-3 | 音声入力 | 中 | Web Speech API でB-2に音声を接続。グラウンドで手袋のまま記録できる |
| B-4 | フィールド図タップ入力 | 中 | スプレーチャートと同じフィールド図をタップして方向・距離を入力 |
| B-5 | プリセット/よく使う結果 | 小 | 使用頻度の高い結果を上位表示、ユーザー別の並び順学習 |
| B-6 | Undo・編集導線の強化 | 小 | 保存直後の取り消し、一覧からのインライン編集拡充 |
| B-7 | オフライン入力の完成度向上 | 中 | 既存 offline-queue の適用範囲拡大と同期状態の可視化 |

## 4. 主な変更対象ファイル

- 打席入力: `app/(protected)/games/[id]/at-bats/page.tsx`（大型ファイルのためコンポーネント分割を推奨）
- 試合作成/編集: `app/(protected)/games/new/page.tsx`, `games/[id]/edit/_EditGameForm.tsx`
- 集計・表示: `lib/stats.ts`, `app/(protected)/stats/page.tsx`, `SprayChart.tsx`
- 型・スキーマ: `lib/supabase/types.ts`, `supabase/migrations/`（Supabase MCP 経由で本番適用可能）

## 5. 進め方（推奨）

1. 上記候補から今回のスコープを確定（A系・B系から数個ずつ推奨）
2. DBマイグレーション作成 → Supabase ブランチまたは直接適用
3. UI実装 → この環境でビルド・動作確認
4. GitHubへpush → Vercel自動デプロイ → 本番確認

※ 本番DBには現在テストデータ相当（games 1件・at_bats 3件）しか無いため、マイグレーションのリスクは低い。
